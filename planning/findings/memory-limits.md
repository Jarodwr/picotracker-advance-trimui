# Sample memory and compatibility at `v2.3.1`

The Advance adapter declares `STORE1_SIZE = 32 * 1024 * 1024` and `STORE2_SIZE = 16 * 1024 * 1024` in [`advSamplePool.h`](../../upstream/picoTracker/sources/Adapters/adv/system/advSamplePool.h). [`advSamplePool.cpp`](../../upstream/picoTracker/sources/Adapters/adv/system/advSamplePool.cpp) allocates two static arrays in distinct SDRAM sections, tracks 32-bit write offsets, chooses a pool for each imported sample, and aligns each sample start to four bytes. A single sample must fit in one pool; the combined 48 MiB is not a contiguous allocation. The STM32 linker script maps the sections to external SDRAM.

The shared pool declares `MAX_SAMPLES = MAX_SAMPLEINSTRUMENT_COUNT * 4` in [`SamplePool.h`](../../upstream/picoTracker/sources/Application/Instruments/SamplePool.h). Under `ADV`, [`Song.h`](../../upstream/picoTracker/sources/Application/Model/Song.h) sets `MAX_SAMPLEINSTRUMENT_COUNT` to `0x40`, giving a maximum of 256 pool entries. The same header fixes instrument and song capacities independently of sample bytes.

The WAV representation stores `size_` and `sampleBufferSize_` as signed `int` and exposes `GetDiskSize()` as `uint32_t` in [`WavFile`](../../upstream/picoTracker/sources/Application/Instruments/WavFile.h). Opening a file computes frames from its data chunk and computes an in-memory 16-bit size. The Advance pool uses that converted size, while [`ImportView`](../../upstream/picoTracker/sources/Application/Views/ImportView.cpp) casts filesystem size to `int` for a preliminary `CheckSampleFits` call. These widths, conversion arithmetic, and fit checks must be audited before any desktop limit is raised. The loader's `<` comparisons also leave some boundary space unused, and alignment needs to be included in capacity calculations.

Recommendation: implement a desktop sample pool with a configurable byte budget and checked `size_t` arithmetic, while preserving a separate **Advance compatibility budget**: two pools of 32 and 16 MiB, a per-sample fit in one pool, alignment, and the existing entry/instrument limits. Warn when a desktop project exceeds device constraints. Do not advertise an arbitrary/unlimited sample size until the WAV, import, serialization and project-load paths have been audited with large fixtures.
